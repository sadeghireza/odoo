# راهنمای جامع ماژول Workflow Engine

> این راهنما برای نسخه فعلی ماژول در شاخه 18.0 تهیه شده و شامل بخش هاي کاربري و فني است.

## 1) معرفي و قابليت ها

ماژول Workflow Engine براي طراحي، اجرا و پايش جريان هاي کاري (Workflow) در اودو ساخته شده است. اين ماژول به شما اجازه مي دهد فرايندها را با حالت ها (State)، گذارها (Transition) و گره هاي شرط (Condition Node) مدل کنيد و آن ها را نسخه بندي و فعال سازي کنيد.

قابليت هاي اصلي:
- طراحي گرافيکي با طراح (Designer) مبتني بر OWL و SVG.
- تعريف حالت ها، گذارها، گره هاي شرط و شاخه هاي ELSE.
- ويرايش شرط ها با Condition Builder و پشتيباني از مدل هدف.
- نسخه بندي فرايند (Revision) و امکان فعال سازي نسخه.
- قواعد امنيتي و سطوح دسترسي.
- ارزيابي شرط ها در موتور اجرا (Engine) با safe_eval.
- پشتيباني از Grid و Snap براي چيدمان دقيق.

## 2) مفاهيم کليدي

### 2.1) Workflow Process و Version
- يک Workflow Process مي تواند چند نسخه داشته باشد.
- فقط يک نسخه مي تواند فعال باشد.
- با Create Revision يک نسخه جديد ساخته و کليه حالت ها و گذارها کپي مي شوند.

### 2.2) State (حالت)
- حالت يک گره معمولي در فرايند است.
- مي تواند شروع (Start) يا پاياني باشد.

### 2.3) Transition (گذار)
- گذار اتصال بين حالت هاست.
- براي گره هاي شرط، گذارها داراي Branch هستند.

### 2.4) Condition Node (گره شرط)
- نوع خاصي از State با شکل لوزي در Designer.
- داراي چند شاخه است که هر شاخه يک گذار است.
- حداقل يک شاخه ELSE لازم است.
- اولين Branchي که شرط آن درست باشد اجرا مي شود.

## 3) نصب و راه اندازي

### 3.1) پيش نيازها
- اودو نسخه 18.0
- نصب وابستگي ها از طريق requirements.txt

### 3.2) فعال سازي ماژول
1. ماژول را در Addons Path قرار دهيد.
2. سرور اودو را با پارامتر -u workflow_engine به روز کنيد.
3. از منوي Apps ماژول را نصب کنيد.

## 4) راهنماي کاربري (ادمين/کاربر)

### 4.1) ايجاد فرآيند جديد
1. از منوي Workflow Engine وارد بخش Process شويد.
2. فرآيند جديد بسازيد و مدل هدف را مشخص کنيد.

### 4.2) طراحي با Designer
- از دکمه Designer وارد طراحي شويد.
- از نوار سمت چپ:
  - Add State: افزودن حالت معمولي.
  - Add Condition: افزودن گره شرط.
  - Add Transition: ورود به حالت لينک سازي.
- براي اتصال حالت ها:
  - Add Transition را فعال کنيد.
  - ابتدا مبدا و سپس مقصد را انتخاب کنيد.
- براي ويرايش يک گذار:
  - روي خط انتقال کليک کنيد.
  - نام گذار را تنظيم کنيد.

### 4.3) تنظيم شرط ها
- اگر گره شرط داريد، بايد براي هر گذار Branch تعريف کنيد.
- براي هر Branch:
  - Branch Expression: عبارت شرط.
  - Branch ELSE: اگر هيچ شرط ديگري برقرار نبود.
- حداقل يک Branch ELSE لازم است.

### 4.4) فعال سازي نسخه
- بعد از تکميل طراحي، از دکمه Activate Version استفاده کنيد.
- فقط يک نسخه فعال مي ماند و نسخه هاي ديگر غير فعال مي شوند.

### 4.5) Revision
- با Create Revision يک نسخه جديد ايجاد کنيد.
- نسخه جديد را در Designer اصلاح کرده و سپس فعال کنيد.

## 5) راهنماي فني (توسعه دهنده)

### 5.1) ساختار مدل ها
- workflow.process: تعريف فرآيند.
- workflow.process.version: نسخه بندي.
- workflow.state: حالت ها (با type = normal | condition).
- workflow.transition: گذارها با branch_expression و branch_is_else.

### 5.2) منطق شرط ها
- شرط ها در گره شرط اجرا مي شوند.
- Engine اولين Branch معتبر را انتخاب مي کند.
- اگر هيچ Branch برقرار نبود، بايد ELSE تعريف شده باشد.

### 5.3) ارزيابي شرط ها
- از safe_eval استفاده مي شود.
- محيط ارزيابي شامل رکورد هدف و context است.

### 5.4) نسخه بندي
- create_revision: کپي تمام حالت ها و گذارها.
- activate_version: غير فعال کردن نسخه هاي ديگر.

### 5.5) Designer (OWL + SVG)
- الگوها در static/src/xml/workflow_designer.xml
- منطق در static/src/js/workflow_designer.js
- استايل ها در static/src/scss/workflow_designer.scss

## 6) تنظيمات و نکات امنيتي
- دسترسي ها از طريق گروه ها و ACL تنظيم مي شود.
- براي کاربران نهايي فقط نمايش لازم است.
- براي طراحي، دسترسي مدير سيستم لازم است.

## 7) عيب يابي (Troubleshooting)

### 7.1) خطاهاي XML
- مطمئن شويد tag ها درست بسته شده اند.
- در صورت خطا، فايل مربوطه را در debug=assets بررسي کنيد.

### 7.2) خطا در Condition Builder
- در صورت خطا، عبارت شرط را ساده کرده و مجددا ذخيره کنيد.
- از استفاده از اپراتورهاي ناشناخته خودداري کنيد.

### 7.3) مشکل در Designer
- کش مرورگر را پاک کنيد.
- Odoo را با --dev=assets راه اندازي کنيد.

## 8) سوالات متداول

**سوال:** چرا شرط ها در گذار نمايش داده نمي شود؟
**پاسخ:** شرط ها مربوط به Branch ها در گره شرط هستند، نه گذار معمولي.

**سوال:** چرا نسخه فعال نمي شود؟
**پاسخ:** ابتدا مطمئن شويد حداقل يک نسخه Draft وجود دارد و خطاي اعتبارسنجي نداريد.

## 9) چک ليست راه اندازي سريع
- [ ] ساخت Process جديد
- [ ] طراحي State و Transition
- [ ] تعريف حداقل يک Branch ELSE
- [ ] ذخيره و Activate نسخه

## 10) راهنماي توسعه و تست
- براي توسعه، از حالت debug=assets استفاده کنيد.
- براي تست شرط ها، با رکوردهاي نمونه سناريو بسازيد.
- قبل از انتشار، نسخه فعال را قفل و مستند کنيد.
